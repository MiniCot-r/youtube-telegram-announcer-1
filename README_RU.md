# YouTube → Telegram: бот-анонсер

Проект проверяет YouTube RSS, публикует новые видео в Telegram-канал и хранит обработанные ID в `posted_videos.txt`. Он поддерживает локальный непрерывный запуск и автоматические запуски через GitHub Actions.

## 1. Что важно знать

- При самом первом запуске бот только сохраняет ID роликов, которые уже есть в RSS, и **не публикует старые видео**.
- В GitHub Actions каждый запуск — отдельный процесс. Поэтому workflow сохраняет обновлённый `posted_videos.txt` обратно в Git-репозиторий.
- Для приватного репозитория GitHub Free ниже выставлено расписание раз в 30 минут. GitHub округляет использование каждого задания вверх до минуты; около 1 440 запусков-минут на 30-дневный месяц укладываются в включённые 2 000 минут, но фактическое время может отличаться.
- Если сделать репозиторий публичным, стандартные GitHub-hosted runners бесплатны для публичных репозиториев, и можно поставить запуск примерно раз в 5 минут. При этом исходный код будет доступен всем. **Не записывайте токен в исходники или в файл, который загружается в GitHub.**
- GitHub не гарантирует запуск ровно по минуте: расписание может задерживаться. Абсолютную бесперебойную работу бесплатно гарантировать нельзя.

## 2. Подготовить токен и канал

1. Создайте/проверьте бота через `@BotFather`.
2. Добавьте бота в Telegram-канал как администратора с разрешением публиковать сообщения.
3. В GitHub используйте только секрет `TELEGRAM_BOT_TOKEN`, описанный ниже. Не вставляйте токен в Python-файл и не загружайте настоящий `.env`.

Если токен когда-либо попал в публичный репозиторий, скриншот или недоверенное место, отзовите его через `@BotFather` и создайте новый.

## 3. Самый простой способ: загрузить проект через веб-сайт GitHub

1. Войдите в [GitHub](https://github.com/) и нажмите **+ → New repository**.
2. Назовите репозиторий, например `youtube-telegram-announcer`. Для рекомендованной настройки выберите **Private**. Можно добавить README или создать пустой репозиторий.
3. Откройте репозиторий и добавьте файлы проекта в его корень: `youtube_telegram_announcer.py`, `requirements.txt`, `README_RU.md`, `.gitignore` и `.env.example`. Не загружайте файл `.env`, если создавали его для локального запуска.
4. Самый важный файл workflow должен лежать именно по пути `.github/workflows/youtube-announcer.yml`. Если веб-загрузка папок неудобна, выберите **Add file → Create new file**, в поле имени файла целиком впишите `.github/workflows/youtube-announcer.yml`, вставьте содержимое одноимённого файла из этого архива и нажмите **Commit changes**. GitHub создаст недостающие папки автоматически.
5. Проверьте, что workflow находится в основной ветке репозитория — обычно `main`.

Если удобнее работать с файлами локально, можно установить GitHub Desktop: создать/клонировать репозиторий, скопировать содержимое распакованной папки проекта в папку репозитория и нажать **Commit to main → Push origin**. Не загружайте `.env`.

## 4. Сохранить токен безопасно в GitHub

1. В репозитории откройте **Settings → Secrets and variables → Actions**.
2. В разделе **Repository secrets** нажмите **New repository secret**.
3. В поле **Name** введите строго `TELEGRAM_BOT_TOKEN`.
4. В поле **Secret** вставьте токен бота и нажмите **Add secret**.
5. Откройте **Settings → Actions → General → Workflow permissions**. Если доступна настройка, разрешите **Read and write permissions**. Workflow также явно запрашивает `contents: write`, чтобы записывать историю.

Не добавляйте настоящий токен в `youtube_telegram_announcer.py`, `.env.example`, README или сообщения коммитов.

## 5. Первый запуск и проверка

1. Откройте вкладку **Actions** в репозитории. Если GitHub спросит, включите Actions.
2. В списке выберите **YouTube Telegram Announcer**.
3. Нажмите **Run workflow → Run workflow** для запуска вручную.
4. Откройте запуск и проверьте логи шагов. При первом успешном запуске появится/обновится `posted_videos.txt` и будет сделан коммит в репозиторий. Уже существующие ролики не будут отправлены в канал.
5. После этого workflow будет запускаться по расписанию автоматически. Когда на YouTube появится новое видео, бот отправит анонс при следующей успешной проверке.

Если шаги завершились ошибкой, откройте шаг с красным крестиком: чаще всего причина — неправильный секрет, у бота нет прав администратора в канале или GitHub не разрешил запись в репозиторий.

## 6. Как настроить интервал

Откройте `.github/workflows/youtube-announcer.yml` и измените строку `cron`.

**Приватный репозиторий на бесплатном тарифе — рекомендуется:**

```yaml
- cron: "7,37 * * * *"
```

Это примерно каждые 30 минут и даёт запас относительно лимита бесплатных минут GitHub Actions.

**Публичный репозиторий — примерно каждые 5 минут:**

```yaml
- cron: "3-58/5 * * * *"
```

Публичный репозиторий делает код видимым, но секрет `TELEGRAM_BOT_TOKEN` не публикуется, пока вы не вставите его в код или логи. В публичных репозиториях GitHub отключает scheduled workflows после 60 дней без активности репозитория, поэтому иногда проверяйте вкладку **Actions**.

Не забудьте сделать commit изменения workflow в основную ветку. Минимальный поддерживаемый интервал GitHub Actions — 5 минут. Запуски могут задерживаться, особенно в периоды высокой нагрузки.

## 7. Как изменить оформление сообщения

В начале `youtube_telegram_announcer.py` меняются:

- `CHANNEL_ID` — ID Telegram-канала;
- `RSS_URL` — RSS-лента YouTube;
- `MESSAGE_HEADER` и `MESSAGE_HEADER_SHORTS` — заголовки;
- `MESSAGE_FOOTER` — подпись и хэштеги;
- `ENABLE_LINK_PREVIEW` — превью ссылки.

`CHECK_INTERVAL_MINUTES` используется при локальном непрерывном запуске. Для GitHub Actions интервал настраивается `cron`-строкой в YAML-файле.

## 8. Локальный запуск на Windows

Создайте рядом с Python-файлом `.env` на основе `.env.example` и запишите в него новый токен. Затем в PowerShell в папке проекта выполните:

```powershell
py -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
python youtube_telegram_announcer.py
```

Для одного запуска проверки (как в GitHub Actions) используйте:

```powershell
python youtube_telegram_announcer.py --once
```

## 9. Shorts

Стандартная RSS-лента YouTube не всегда достоверно обозначает Shorts. Скрипт использует ссылку вида `/shorts/` или хэштег `#Shorts`, если они есть. В противном случае публикует нейтральный анонс со ссылкой на YouTube.

## 10. Ограничение по повторам

После подтверждённой отправки сообщения Telegram ID сразу записывается в локальный файл, а GitHub Actions сохраняет этот файл в репозиторий даже при ошибке на последующем ролике. Как и у большинства ботов, остаётся редкий крайний случай: Telegram мог принять сообщение, а соединение оборвалось до ответа API; поскольку у `sendMessage` нет ключа идемпотентности, в такой ситуации теоретически возможен повтор при следующем запуске.
